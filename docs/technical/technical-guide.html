Section 2

2System architecture

One container image runs the whole app: pages, API and the MCP endpoint. State is loaded from Postgres at the start of each request and saved back at the end.

Why the workspace is one row

The whole practice workspace is one JSON document (workspace_state.data) with an integer version. A request loads it into memory, changes it with plain TypeScript, and writes it back only if the version hasn't moved. This keeps services simple and synchronous, and makes every save all-or-nothing, at the cost of size: see the 6 MB limit in Section 6.

Scaling limitTwo people saving at the same moment conflict and one retries (freshWrite handles this on the server). Moving to row-per-entity tables is the planned path if practices or concurrency grow a lot.

Adding a secretThe buildspec rewrites the Lambda's environment from a fixed list on every deploy. Nightly schedule

EventBridge Scheduler workpaper-xero-nightly runs cron(0/10 22-23 * * ? *), London time: every 10 minutes from 22:00 to 23:50. It invokes the Lambda through the role workpaper-xero-nightly-scheduler, with input {"key": HMAC-SHA256(AUTH_SECRET, "xero-auto-sync")}. Each run checks a batch of Xero connections, pulls at most one changed ledger, then runs nightly learning. If AUTH_SECRET changes, regenerate the key, or every run gets a 403.

5Life of a request

src/app/api/v1/engagements/[id]/learn/route.ts route pattern
export const dynamic = 'force-dynamic';

export async function POST(req, props) {
  try {
    await syncIn();                  // 1
    const { id } = await props.params; // 2
    const actor =
      requireEngagementAccess(req, id);  // 3
    if (!REVIEWER_UP.includes(actor.role))
      throw new ServiceError('Only a reviewer…',
                             403, 'FORBIDDEN');
    const out = learnFromConfirmed(
      actor.firmId, [id], actor);           // 4
    await syncOut();                 // 5
    return jsonResponse(out);
  } catch (err) {
    return errorResponse(err);      // 6
  }
}
  1. Load the latest saved workspace into the server's in-memory db. Always first.
  2. In this Next version, params is a Promise.
  3. Reads the signed session cookie and looks the user up afresh, so a removed member loses access at once. It also checks the engagement is in their firm and on a client they are assigned to.
  4. The service changes db and writes the audit log.
  5. Save. It throws if someone else saved first.
  6. Turns ServiceError (status and code), GuardError and unknown errors into JSON responses. These three helpers are among the most-called functions in the codebase.
src/proxy.ts the sign-in gate
const PUBLIC_PATHS = ['/login', '/signup', …,
  '/api/mcp', '/api/v1/integrations/xero/auto-sync'];

export function proxy(request) {
  if (PUBLIC_PATHS.some(p => path === p
      || path.startsWith(p + '/'))) return next();
  // headers are never trusted, only the signed cookie
  if (verifySessionToken(cookies.get(SESSION_COOKIE)))
    return next();
  if (path.startsWith('/api/')) return json(401);
  return redirect('/login?from=' + path);
}
  1. Runs before every page and API call, except static files.
  2. Public paths guard themselves: reset and invite tokens, the MFA challenge cookie, MCP bearer tokens, and the scheduler's HMAC key.
  3. auth.ts doesn't import db, so the proxy can check sessions without loading the workspace.
  4. Pages redirect to login and keep the original path in from, so an assistant's connection request survives sign-in.
Section 6

6Workspace storage and sync

src/lib/server/store.ts optimistic versioning
export async function syncIn() {
  const state = await readState();
  if (state.data) db.importState(clone(state.data));
  serverVersion = state.version;
}

export async function syncOut() {
  const v = await writeState(serverVersion, db.exportState());
  if (v === null) throw new Error('Workspace was changed by someone else…');
  serverVersion = v;
}
// writeState: UPDATE workspace_state SET version = version + 1, data = $2
//             WHERE id = $1 AND version = $3 RETURNING version

export async function freshWrite(apply) {
  for (let attempt = 0; ; attempt++) {
    await syncIn();
    const out = apply();
    try { await syncOut(); return out; }
    catch (e) { if (attempt >= 1 || !conflict(e)) throw e; }
  }
}
  1. Without DATABASE_URL (local dev) the same API keeps state in memory, mirrored to .workspace_state.json (on Lambda, /tmp).
  2. The WHERE version = $3 is the concurrency control: a stale writer updates no rows and gets null.
  3. freshWrite is for work that follows something slow (an AI call, a Xero pull). It reloads, re-applies the change to the latest state, and tries once more.
  4. Attachments are stored in a separate files table so workspace saves stay small.

Server-managed collections

state-guard.ts marks some collections as server-managed: the browser may read them, but its saves cannot change them. They change only through their own audited API routes. These are journals (adjustments), sign-offs, TB snapshots and lines, ledger transactions, connections, credentials and invites. Credentials, invites, uploads and connection tokens are never sent to the browser at all.

The 6 MB response limitA Lambda response can be at most 6 MB. publicSlice keeps the download small: it leaves out ledger transactions (fetched per engagement from /engagements/[id]/transactions), drops raw_json from every TB snapshot, and sends lines only for each engagement's latest snapshot. Gzip does the rest. If "Could not load the workspace" comes back, look here first.

Section 8

8Security and access

Sign-in

  • Passwords are hashed in auth.ts. Hashes live only in server-only credentials.
  • blynt_session: an HttpOnly, SameSite=Lax cookie signed with AUTH_SECRET, valid for 12 hours.
  • MFA: TOTP (totp.ts), backup codes, and a 30-day trusted-device cookie. It is enforced only when MFA_REQUIRED=true.
  • Repeated failed sign-ins lock the account out (isLockedOut).
  • InactivityHandler signs idle users out.

Isolation

  • Every API route resolves the actor from the cookie, then checks firm and assigned clients (requireEngagementAccess, requireWorkpaperAccess…).
  • Below partner, members see only their assigned clients (visibleClientIds).
  • The browser receives only its own firm's slice, without secrets.
  • Files can be read only by the practice that uploaded them, through engagements the user can open.
  • Xero and QuickBooks tokens are stored encrypted (XERO_TOKEN_KEY).

Section 9

9Trial balance, mapping and learning

Import (tb-import.ts)

Every source (CSV, Xero, QuickBooks) ends in importTrialBalance(actor, engagementId, lines, source). It checks that each line has a name and real amounts, that codes are unique (a missing code becomes ACC-NAME), and that each line is under £1bn. It rejects an unbalanced TB with the difference, stores an immutable snapshot hashed with SHA-256, records what moved since the last import, and maps every line through runGated.

src/lib/server/gate.ts runGated()
const rule = findRule(firmId, ruleType, keys,
                     { clientId, supplier });
if (rule) {
  rule.times_used += 1;
  return { value: decode(rule.target_value),
    confidence: 100, gate: 'ready',
    source: 'rule', accepted: true, … };
}
const p = opts.ai();
if (!p) return { value: null, gate: 'exception', … };
const gate = gateFor(firmId, outputType, p.confidence);
return { …p, gate, source: 'ai',
  accepted: gate === 'ready'
    && thresholdsFor(firmId, outputType).auto_accept };
  1. Rule keys are exact typed keys (code:4000, name:sales ledger) or wildcard name patterns (*rent*).
  2. The AI function is called only when no rule matched, so a rule saves both cost and time.
  3. Thresholds are set per output type in Practice settings.
  4. The same interface is meant for other outputs too: extraction, journals and findings.

Learning (learning.ts)

  • Nightly: after the Xero sync, learnNightly() runs once per practice every 20 hours. It turns each client's latest confirmed mapping per code into a client rule (code:<x>).
  • Learn now: the Mapping page button (reviewer and above) runs the same step for one engagement straight away.
  • Examples for the AI: mappingExamples() sends up to 40 confirmed mappings to suggest_mapping, the same client's first. They come only from the user's own practice.

Tax library (lib/tax.ts)

Built-in, dated UK VAT entries sourced from GOV.UK: rates (17.5% to 2011-01-03, then 20%, plus 5% and 0%), registration and deregistration thresholds, flat rate, cash and annual accounting limits, and the flat-rate categories. Practices can add their own entries (firm.settings.tax_entries, manager and above), which take priority. inForce(key, date) and inPeriod(key, from, to) answer "what applied when". vatFactsFor(engagementId) gives the AI review the client's scheme, rates, thresholds and warnings, such as an unregistered client over the threshold.

Adding an AI task

Define a TaskDef in ai/tasks/*.ts (id, version, module, schema, build(input)) and add it to ai/catalog.ts. Call run(task, input, ctx) from ai/services.ts, and send the result through the gate or a confirm step. Bump version when the prompt changes, so logs show which version produced which output.

MCP server (lib/server/mcp)

Outside assistants (Claude, ChatGPT and others) connect with OAuth 2.1 and PKCE: /.well-known/*, /api/oauth/register|authorize|token|revoke. They then call JSON-RPC at /api/mcp, which is stateless so it suits Lambda. Each call is checked against the user as they are now (role, practice, assigned clients), the practice's MCP switch and tool list, and the token's scope, and every call is logged. Tools: search_workpapers, get_client_summary, get_account_details, find_missing_documents, generate_report, create_reconciliation_draft, retrieve_review_exceptions, get_workpaper_status. It is off unless MCP_ENABLED=1.

Test conventions

  • Server tests drive the real db and services in memory. Reset the collections a test depends on (for example clear account_mappings before seeding).
  • External calls (Xero, providers, GOV.UK) are passed in as fetchFn or mocked. LIVE_AI enables the few live AI tests.

  • Money assertions compare bigint pence, never formatted strings.

How to add…

An API route

Create src/app/api/v1/<area>/route.ts following the pattern in Section 5: syncIn, a require…Access check, a role check, the service call, syncOut, and the two response helpers. Put the logic in a service under lib/server, not in the route. Add a test in src/__tests__.

A working paper

Add a template to templates.ts (ref, title, lead codes, procedures), a calculator in lib/workpapers/, a screen in components/workpaper/papers/ registered in papers/index.ts, and checks in engine.ts.

A server-managed collection

Add it to the Database class in db.ts and its type to models.ts. If only the server may change it, add it to SERVER_MANAGED in state-guard.ts, and to the server-only list if the browser must never see it.

A scheduled job

Hang it off the auto-sync route (the one pass-through path), as nightly learning and the weekly tax check already do, and keep it idempotent with a "last ran" check, because the schedule fires every 10 minutes in its window.
